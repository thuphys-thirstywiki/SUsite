# 技术扫盲

本 Wiki 用 Git 管理、Markdown 编写，理解一点基础技术能让投稿和协作更顺利。这个分类面向完全零基础的同学，用最少的术语讲清"够用"的知识。

## 本分类包含什么

- [Git 基础](/tech/git-basics) — 版本控制是什么、核心概念、常用命令与应急修复
- [命令行基础](/tech/bash-basics) — 终端是什么、怎么打开、常用命令
- [编辑本 Wiki 实战](/tech/edit-wiki) — 从写一个词条到发布上线的完整流程

## 需要先了解吗

不需要。本分类从零讲起，每个页面 10–20 分钟能读完，读完就能上手投稿。

::: tip 先读哪个
只想快速投稿、不想学太多 → 直接读 [编辑本 Wiki 实战](/tech/edit-wiki)。
想理解背后的原理、能独立处理常见问题 → 从 [Git 基础](/tech/git-basics) 开始。
:::

## 常见术语速览

| 术语 | 一句话解释 |
| --- | --- |
| Git | 记录文件每次修改的"存档系统"，可随时回退到任意版本 |
| 仓库（Repository） | 用 Git 管理的一个项目文件夹 |
| 提交（Commit） | 一次"存档"，记录了当时的文件快照和修改说明 |
| 分支（Branch） | 并行的开发线，互不干扰，最后合并 |
| 远程（Remote） | 存在服务器上的仓库副本（本 wiki 即 GitHub） |
| Markdown | 用简单符号标记格式的纯文本，本 wiki 的写作语言 |
| Pull Request（PR） | 申请把你的改动合并进主分支，管理员审核后通过 |

::: tip 建议
遇到不懂的术语，先看本分类的速览表，再按需深入对应页面。
:::
